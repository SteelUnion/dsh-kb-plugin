# DSH-КБ-plugin · 插件设计局

**КБ** = конструкторское бюро（俄语「设计局」）。

一个把 DeepSeek Harness 的 cordis 服务图画成三维分子、并在图边上直接设计插件链的 DSH 插件。

---

## 它是什么（大白话）

DSH 内部有一百多个「服务」——`sessions` 管会话、`tools` 管工具、`llm` 管模型调用。
写插件的时候，你要知道**有哪些服务、它们互相怎么依赖、你的插件该挂在哪**。

这个插件把这些关系画出来：**14 个球，每个球是一层，球里是这一层的服务点，球之间的线是层与层之间的依赖。**

你可以转它、点它、搜它。选中一个服务，它会告诉你**这个服务依赖谁、谁依赖它**。

---

## 已经能用的

### 三维服务图

- **14 个球**（host 5 层 / client 9 层），**125 个服务**，**59 组层间依赖**
- **拖动旋转、滚轮缩放、双击复位**
- **点球聚焦**：球放大居中，其它球缩成可点的小点，700ms 平滑飞过去
- **透视**：远的球小、暗、被近的盖住（焦距 900）
- **曲线键**：跨面琥珀色、同面石板灰，弯度随跨面与否变化
- **分级显示**：全景只看球名和层号水印，聚焦才展开球内服务点和缩写
- **左下角快捷栏**：14 个球的按钮 + 重置视角

### 选中服务后

- **右侧面板**：服务中文说明、方法清单（签名 + 白话）、所属球
- **依赖 / 被依赖**：分组、带计数、每个 chip 可点跳转，超过 4 个给筛选框
- **青色线** = 它依赖谁，**橙色线** = 谁依赖它，带箭头和端点圆
- **跨球**：依赖线穿过球壁画到别的球里
- **全景也保留**：切到宏观，选中的服务点仍标黄 + 显示名字

### 搜索

- 顶部搜索框，输服务名 / 中文说明，**回车直接定位**到那个服务所在的球

### 插件链

- **右侧面板切「插件链」**，三维图不动，可以对照着看
- **按拓扑分层画成 SVG**：同层并排 = 可并发，层间箭头 = 触发顺序
- **边上 A/O 标记**：A = 必要（必须等到），O = 可选（有就带上、不阻塞）
- **点边选中 → 操作栏切 A/O 或删除**
- **`⇢ 连到…`**：点起点 → 点目标 → 连一条边
- **前后添加自检**：链条里已有同一模块时**复用不重复建**，直接连回它（含「堂兄弟」情形）
- **防环**：加边前检查会不会成环
- **生成方案**：导出九节 Markdown —— Mermaid 图、逐条边落成什么代码、节点清单、触发规则、`inject` 清单、官方插件形态、待你决定的事项、不确定的地方

## 安装

目前只能手工装（desktop profile 的 `dsh plugin` 被 CLI 硬拒）：

1. 把本目录放到任意位置
2. 改 `~/.dsh/profiles/desktop/package.json`：
   ```json
   "dsh": { "profile": { "bundles": [ ..., "dsh-kb-plugin" ] } },
   "dependencies": { ... , "dsh-kb-plugin": "link:<本目录绝对路径>" }
   ```
3. `cd ~/.dsh/profiles/desktop && pnpm install`
4. 重启 DSH
5. 左侧栏会出现「插件设计局」图标

**注意**：三处（`bundles` / `dependencies` / `node_modules`）必须同时对得上，缺一处会启动失败。

## 它提供什么

**给插件作者**：不用翻源码就能知道「有哪些服务、怎么互相依赖、我的插件该挂哪、inject 要写什么」。

**给 DSH 用户**：一张能转能点的架构图，看懂这个工具到底由什么组成。

## 技术事实

| 项 | 值 |
|---|---|
| 内核基线 | cordis 4.0.5 / dsh 0.2.1-rc.5 |
| 客户端产物 | 单文件 `client.js`，约 335 KB（场景数据内联） |
| 依赖 | 零运行时依赖 |
| 构建 | `node emit-client.mjs`（在测试目录里）把模板 + 数据合成 `client.js` |
